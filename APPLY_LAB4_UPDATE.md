# Как применить исправления ЛР4

1. Остановите локальный сервер (Ctrl+C).
2. Распакуйте этот архив в отдельную папку. В нём только новые/изменённые файлы,
   с путями от корня проекта. Нет .venv, .git и полной замены README.
3. Скопируйте содержимое в основной проект с объединением папок и заменой файлов.
   Не заменяйте целиком папку src пустой папкой обновления: в архиве только изменения.
4. Пакет остаётся src/salary_calculator/. Не переименовывайте его в payroll:
   этот комплект подготовлен для последнего присланного архива с Mac.
5. Не удаляйте начальную ревизию миграции. Новая ревизия применяется поверх неё.
   Существующие db/models.py и db/mappers.py заменяются фасадами: новые определения
   находятся в db/orm и db/mapping; старые импорты продолжают работать.
6. Из корня проекта на Mac:

       uv sync --frozen
       uv run ruff check .
       uv run ruff format --check .
       uv run pytest

   Этот pytest без TEST_DATABASE_URL должен дать 21 passed и 18 skipped.
   Пропуски SQL-тестов не означают проверку PostgreSQL.

   На Windows каждую команду uv можно начинать с `py -m uv`.

7. С установленным и запущенным Docker:

       docker compose up --build -d
       docker compose ps
       docker compose logs migrations web
       docker compose --profile test run --build --rm tests

   Последняя команда использует отдельный db-test и должна дать 39 passed,
   без failed/skipped. Для нового кода не выполняйте вручную revision --autogenerate:
   готовая новая ревизия уже включена.

8. Открыть http://127.0.0.1:8000, войти admin/admin, сохранить настройки и сотрудника.
   После `docker compose down` и `docker compose up -d` данные должны остаться.
   Не используйте down -v: для штатной остановки удалять данные не требуется.
9. Для запуска CLI с работающим сервисом db:

       uv run python src/main.py

   Локальные параметры по умолчанию: salary/salary, localhost:5432/salary.
   Веб без Docker, после применения миграций: `uv run python src/web_main.py`.
   Деморежим без БД явно: `STORAGE_BACKEND=memory uv run python src/web_main.py`.

Сведения о найденных проблемах, выполненных проверках и границе проверки Docker:
`docs/LAB4_AUDIT.md`. Полный список файлов: `docs/LAB4_CHANGED_FILES.md`.

README команды целиком не заменяется. Краткий текст для добавления дан в сообщении
с архивом; актуальные инструкции находятся в docs/INTEGRATION_CHECKLIST.md.

Рекомендуемые коммиты после переноса соответствующих групп файлов:

1. feat: добавить ORM-связи и классы-мапперы для PostgreSQL
2. fix: согласовать миграции, транзакции и ограничения SQL-хранилищ
3. fix: исправить Docker-запуск и изолировать интеграционные тесты
4. docs: обновить ER-схему и инструкцию сдачи лабораторной 4

Можно одним коммитом:

    fix: завершить интеграцию PostgreSQL и критерии лабораторной 4

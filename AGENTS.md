# Инструкции ИИ-агенту: Salary Calculator

## Цель проекта

Создать учебный сервис для расчёта зарплаты сотрудников малых предприятий. Предприятие задаёт собственные реквизиты, должности, ставки, надбавку за полный год стажа и норму смен на период. Базовый расчёт: начислено = ставка за смену × фактически отработанные смены; НДФЛ = 13 % от начисленного; к выплате = начислено − НДФЛ. Ставка НДФЛ в данной учебной модели фиксирована и не входит в настройки организации.

## Текущий этап: лабораторная работа №3

- Исполняемая программа — CLI на стандартной библиотеке Python 3.11+ с хранением данных InMemory. Все данные исчезают после завершения процесса. Точка входа — `src/main.py`.
- Установленные через `uv` FastAPI, SQLAlchemy, Alembic и Pydantic записаны в зависимостях для последующих работ, но в исполняемой логике ЛР №3 не используются.
- Доступные сценарии: учебный вход бухгалтера; настройка организации, должностей и ставок; добавление, просмотр, изменение и увольнение сотрудника; выбор периода и нормы; формирование и заполнение табеля; расчёт и просмотр ведомости; текстовый расчётный листок; закрытие периода.
- Текущий интерфейс представляет действия будущих веб-форм через меню терминала. В этом этапе нет браузера, HTTP API, PostgreSQL, Docker, PDF и долговременного хранения. Не описывайте их как уже работающие.
- Точный охват и ограничения см. в `README.md` и `docs/IMPLEMENTATION_SCOPE.md`; при несовпадении с пожеланиями или старым ТЗ сначала уточняйте, относится ли изменение к ЛР №3 или следующему этапу.

## Распределение ответственности и структура

- Инженер 1: модели предметной области, настройка тарифов и стажа, сотрудники, стратегия расчёта, НДФЛ и расчёт ведомости: `src/salary_calculator/models.py`, `employee_service.py`, `organization_service.py`, `calculators.py`, `payroll_service.py`.
- Инженер 2: взаимодействие с бухгалтером: `src/salary_calculator/cli/app.py` содержит команды и переходы меню; `cli/input_helpers.py` повторно запрашивает некорректные значения; `cli/presenters.py` переводит предметные объекты в текст. Не дублируйте формулы зарплаты и правила хранения в CLI.
- Инженер 3: точка входа и сборка зависимостей (`src/main.py`), абстрактные интерфейсы (`contracts.py`), InMemory-репозитории (`repositories.py`), календарь, табель, авторизация, тесты, документация и настройки проекта.
- `tests/` содержит проверки пользовательских сценариев и правил расчёта; `docs/` — архитектуру, охват ТЗ и план испытаний. В корне находятся `README.md`, `AGENTS.md`, `.gitignore`, `pyproject.toml` и `uv.lock`.

## Правила реализации

1. Перед изменением прочитайте соответствующие модули и документы. Сохраняйте существующие сценарии, термины и утверждённые пункты 1–4 общего README команды; не заменяйте их отдельным README комплекта ЛР №3.
2. Держите `src/main.py` коротким: он соединяет реализации и запускает `SalaryCalculatorCLI`. В `cli/app.py` собирайте ввод, вызывайте сервис и показывайте результат. Правила предметной области размещайте в сервисах/моделях, текстовое представление — в presenters.
3. Для сменяемых интерфейсов используйте `abc.ABC` и `@abstractmethod` из стандартной библиотеки, как в `contracts.py`; не вводите `typing.Protocol` без обсуждения с командой и преподавателем. Для денег используйте `Decimal`, для даты — `datetime.date`; расчёты округляйте до копеек по существующему правилу.
4. Проверяйте ввод на границе CLI для понятных повторных запросов и в сервисах для сохранности бизнес-правил. Отрицательные значения, нецелые смены и превышение нормы не должны записываться; ошибка не должна завершать работу меню. Незаполненная строка табеля отличается от заполненной нулём смен.
5. Не разрешайте менять закрытый период. После правки табеля отмечайте существующую ведомость устаревшей; перерасчёт существующей ведомости запрашивает подтверждение. Не уничтожайте ранее корректную ведомость из-за ошибочного нового ввода.
6. Сохраняйте аннотации типов и docstring сразу после объявления классов и функций; не вставляйте поясняющие комментарии внутрь алгоритмов. Избегайте посторонних библиотек в исполняемой логике ЛР №3.
7. Меняйте минимально необходимый набор файлов. При изменении пользовательского сценария обновляйте связанные описания и осмысленные проверки; не называйте PDF или веб-прототип результатом данного CLI.

## Проверка и запуск

Из корня проекта: `python src/main.py` (или `uv run python src/main.py`). Учебная учётная запись: `admin` / `admin`. Для проверки кода: `uv run ruff format --check .`, `uv run ruff check .`, `uv run pytest`. При изменении сценария дополнительно пройдите его вручную через меню. Не утверждайте, что проверки выполнены, если они не запускались.

## Дальнейшее развитие

В следующем этапе консольные сценарии можно перенести в веб-формы: главная страница Salary Calculator, боковое меню, сотрудники и форма добавления, табель, ведомость, расчётный листок. Сохраняйте взаимодействие через сервисный слой, чтобы веб-интерфейс не содержал формул расчёта. Расширение типов графиков, правил оплаты и налогового учёта требует отдельного согласования требований и тестов; текущая реализация поддерживает только описанную базовую схему оплаты по сменам.

## 1. Общие сведения - Куропятников 
### 1.1. Наименование системы
Полное наименование разрабатываемой системы — «Автоматизация процесса расчета заработной платы сотрудников малого предприятия».
Краткое наименование системы — Salary Calculator.
### 1.2. Основание для разработки
Основанием для разработки является задание на выполнение лабораторных работ по дисциплине «Программная инженерия» для студентов второго курса факультета электроники и вычислительной техники Волгоградского государственного технического университета.
Разработка выполняется в соответствии с требованиями кафедры «Системы автоматизированного проектирования и поискового конструирования» и техническим заданием проекта.
### 1.3. Заказчик и пользователи системы
Заказчиком и принимающей стороной проекта является кафедра «Системы автоматизированного проектирования и поискового конструирования» Волгоградского государственного технического университета.
Основным пользователем системы является бухгалтер или другой уполномоченный сотрудник малого предприятия, отвечающий за ведение кадровых данных, учет рабочего времени и расчет заработной платы.
### 1.4. Цель разработки
Целью разработки является создание веб-системы, автоматизирующей расчет заработной платы сотрудников малого предприятия на основании фактически отработанного времени.
Система должна сократить время подготовки расчетной ведомости, уменьшить количество ошибок ручного ввода, обеспечить единообразное применение правил расчета и предоставить пользователю возможность формирования расчетных листков сотрудников.
Для достижения поставленной цели система должна обеспечивать:
* ведение справочника сотрудников и должностей;
* формирование табеля учета рабочего времени;
* учет отработанных смен, дней больничного и отпуска;
* автоматическое определение ставки сотрудника;
* расчет начисленной заработной платы;
* расчет НДФЛ 13%;
* определение итоговой суммы к выплате;
* формирование расчетной ведомости;
* формирование индивидуальных расчетных листков;
* хранение подтвержденных данных в PostgreSQL;
* запуск всех компонентов через Docker Compose.

## 2. Назначение программных средств
### 2.1. Функциональное назначение
Система Salary Calculator предназначена для автоматизации кадровых, учетных и расчетных операций, связанных с начислением заработной платы сотрудникам малого предприятия.
Система предоставляет пользователю возможность:
* создавать и редактировать карточки сотрудников;
* вести справочник должностей;
* хранить сведения о дате приема, ИНН и статусе сотрудника;
* формировать табель за выбранный месяц и год;
* учитывать отработанные смены, больничные и отпуска;
* проверять соответствие введенных данных календарной норме;
* автоматически определять ставку сотрудника;
* рассчитывать начисление, НДФЛ и сумму к выплате;
* просматривать расчетную ведомость;
* формировать индивидуальные расчетные листки;
* печатать и выгружать расчетные листки в PDF;
* настраивать реквизиты и правила работы организации.
В базовой версии системы применяется схема оплаты за рабочую смену. Размер ставки определяется на основании должности и стажа сотрудника.
Расчет выполняется по следующим формулам:
Начислено = Ставка за смену × Количество отработанных смен

НДФЛ = Начислено × 13%

К выплате = Начислено − НДФЛ
Денежные вычисления выполняются серверной частью с использованием типа Decimal. Результаты расчета сохраняются в базе данных и используются для формирования расчетной ведомости и расчетных листков.
### 2.2. Эксплуатационное назначение
Система предназначена для эксплуатации бухгалтером или другим уполномоченным сотрудником малого предприятия.
Для работы с системой пользователь должен обладать базовыми навыками использования веб-браузера. Знание программирования, SQL и администрирования не требуется.
Работа выполняется через веб-интерфейс. Установка отдельного клиентского приложения на рабочее место пользователя не требуется.
Система поддерживает работу в следующих браузерах:
* Google Chrome;
* Яндекс Браузер;
* Mozilla Firefox;
* Microsoft Edge.
Рекомендуемое разрешение экрана — 1920×1080. Минимальное поддерживаемое разрешение — 1366×768.
Серверные компоненты системы запускаются в контейнерах Docker. Подтвержденные сведения о сотрудниках, табелях и расчетах сохраняются в PostgreSQL и не должны теряться после перезапуска контейнеров.

## 3. Описание системы и сценарии использования
### 3.1. Назначение клиентской и серверной частей
Клиентская часть предоставляет бухгалтеру единое рабочее пространство для ведения справочника сотрудников, заполнения табеля, запуска расчета заработной платы, просмотра ведомости и получения расчетных листков.
Серверная часть повторно проверяет входные данные, выполняет бизнес-правила и финансовые вычисления, сохраняет подтвержденные результаты в PostgreSQL и возвращает их клиентской части.
Frontend не является источником окончательных данных о ставках, начислениях и удержаниях. Все финансовые показатели должны подтверждаться сервером.
Для поддержки различных предприятий интерфейс содержит раздел настроек организации. Пользователь может задавать реквизиты, рабочий график, производственный календарь и схему оплаты по умолчанию.
Backend реализуется на Python 3.12 с использованием Django и Django REST Framework. Операции, затрагивающие несколько связанных записей, выполняются в транзакциях.
### 3.2. Верхнеуровневая схема взаимодействия
1. Пользователь выполняет действие в веб-интерфейсе.
2. Frontend проверяет обязательность и формат введенных значений.
3. Клиентская часть формирует HTTP-запрос к серверному API.
4. Backend проверяет авторизацию, структуру запроса и допустимость значений.
5. Сервисный слой выполняет требуемую бизнес-операцию.
6. Изменения связанных сущностей записываются в PostgreSQL в одной транзакции.
7. Сервер возвращает JSON с результатом или структурированным описанием ошибки.
8. Frontend обрабатывает ответ и обновляет состояние интерфейса.
### 3.3. Сценарии использования
3.3.1. Создание карточки сотрудника
Действующее лицо: бухгалтер или уполномоченный пользователь.
Предусловия:
* пользователь авторизован;
* организация настроена;
* в справочнике существует хотя бы одна должность.
Основной сценарий:
1. Пользователь открывает раздел «Сотрудники».
2. Пользователь нажимает кнопку «Добавить сотрудника».
3. Система открывает модальное окно.
4. Пользователь вводит ФИО, выбирает должность, указывает дату приема и ИНН.
5. Frontend проверяет обязательность и формат полей.
6. Backend повторно проверяет полученные данные.
7. Сервер проверяет уникальность ИНН внутри организации.
8. Система определяет ставку по должности и стажу.
9. Карточка сотрудника сохраняется в PostgreSQL.
10. Обновленная запись отображается в справочнике сотрудников.
Ошибочные ситуации:
* пустые обязательные поля;
* ИНН содержит не 12 цифр;
* дата приема находится в будущем;
* сотрудник с таким ИНН уже существует;
* выбранная должность отсутствует или отключена.
При обнаружении ошибки карточка не сохраняется, а пользователь получает понятное сообщение.
3.3.2. Формирование табеля учета рабочего времени
Основной сценарий:
1. Пользователь открывает раздел «Табель учета времени».
2. Пользователь выбирает месяц и год.
3. Frontend передает выбранный период серверу.
4. Backend определяет границы периода.
5. Сервер выбирает сотрудников, состоявших в штате в выбранном периоде.
6. Система получает норму смен из производственного календаря.
7. Backend создает отсутствующие строки табеля или загружает существующий табель.
8. Frontend отображает таблицу сотрудников.
Если табель уже существует, сохраненные сведения загружаются без создания дубликата.
Если период закрыт, табель открывается только для просмотра.
3.3.3. Внесение и валидация данных в табеле
Пользователь вводит для каждого сотрудника:
* количество отработанных смен;
* количество дней больничного;
* количество дней отпуска.
Frontend автоматически рассчитывает показатель «Всего учтено» и сравнивает его с нормой периода.
Сервер повторно проверяет:
* целочисленность значений;
* отсутствие отрицательных значений;
* принадлежность строки выбранному табелю;
* соответствие суммы учтенных дней норме периода;
* возможность редактирования выбранного периода.
При наличии ошибки возвращается ответ 400 Bad Request. Сервис продолжает работу, а некорректные данные не сохраняются.
Сохранение табеля выполняется одной транзакцией. Если хотя бы одна строка содержит ошибку, весь пакет изменений откатывается.



3.3.5. Формирование расчетного листка - Куропятников 
1. Пользователь открывает рассчитанную ведомость.
2. Пользователь выбирает сотрудника.
3. Frontend запрашивает сохраненную строку расчета.
4. Backend проверяет права пользователя и наличие ведомости.
5. Сервер возвращает ставку, количество смен, начисление, НДФЛ и сумму к выплате.
6. Система открывает модальное окно расчетного листка.
7. Пользователь может распечатать листок или скачать его в PDF.
Расчетный листок формируется на основании сохраненной ведомости. Изменение текущих ставок и справочников не должно изменять ранее подтвержденный расчет.
3.3.6. Настройка организации
Пользователь может настроить:
* наименование организации;
* ИНН и КПП;
* юридический адрес;
* основной график работы;
* производственный календарь;
* схему оплаты по умолчанию;
* правила округления;
* валюту расчетов.
Изменение настроек применяется к последующим операциям и не должно автоматически изменять закрытые расчетные периоды.



4.2.5. Веб-интерфейс - Куропятников
Веб-интерфейс должен содержать:
* главное рабочее окно;
* боковое навигационное меню;
* справочник сотрудников;
* форму добавления сотрудника;
* табель учета рабочего времени;
* расчетную ведомость;
* модальное окно расчетного листка;
* настройки организации.
В верхней части страниц отображается название Salary Calculator, а под ним — название текущего раздела.
Основные разделы бокового меню:
* сотрудники;
* табель учета времени;
* расчет зарплаты;
* настройки организации.
Интерфейс не должен использовать сплошные белые подложки под содержимым страниц.
Формы должны показывать состояния:
* загрузка;
* пустые данные;
* успешное выполнение;
* ошибка валидации;
* серверная ошибка;
* отсутствие доступа.
Цвет не должен использоваться как единственный способ обозначения ошибки.
При ширине менее 820 пикселей боковое меню должно переходить в компактный режим.
При ширине менее 540 пикселей формы должны перестраиваться в одну колонку.

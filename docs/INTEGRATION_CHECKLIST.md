# Интеграционные проверки инженера 3

Выполнять на живом PostgreSQL. Команда: `uv run pytest tests/integration -v`
при заданном `DATABASE_URL` (без него тесты пропускаются).

1. `alembic upgrade head` создаёт все восемь таблиц на чистой БД.
2. `alembic downgrade base` на отдельной тестовой БД удаляет их без ошибок.
3. `GET /api/state` возвращает `storage_mode: "PostgreSQL — данные в базе данных"`.
4. Настройка организации и должностей сохраняется: после перезапуска
   сервера данные на месте.
5. Идентификаторы сотрудников идут по порядку и продолжаются после
   перезапуска (Identity, а не max+1).
6. Повторный ИНН сотрудника отклоняется с понятной ошибкой, прежние
   данные не искажаются.
7. Табель создаётся один раз на период: повторное формирование возвращает
   ту же запись; в БД UNIQUE `(year, month)` не даёт дублей.
8. Незаполненный участник табеля — строка с тремя NULL в `timesheet_rows`.
9. Правка строки табеля увеличивает `revision`; после правки ведомость
   показывается как устаревшая.
10. Расчёт ведомости: 2500 × 20 смен = 50000, НДФЛ 6500, выплата 43500
    (проверка по TEST_PLAN); строки ведомости содержат снимок карточки.
11. Ошибка на одной строке не оставляет частичной ведомости: транзакция
    откатывается.
12. Закрытие периода: только при совпадении `source_revision` и
    `revision`; закрытый табель не правится, период не пересчитывается.
13. При недоступной БД интерфейс получает `StorageError` (503), а не
    текст SQL-ошибки.
